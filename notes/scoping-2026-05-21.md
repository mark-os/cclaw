# Scoping Notes — 2026-05-21

## Pogoplug Service Pattern (from nullclaw)

nullclaw uses SysVinit on pogoplug (Debian Bookworm armel, no systemd):
- `/etc/init.d/{botname}` — init script per bot instance
- `wait_for_network()` — polls DNS (nslookup) before starting, 60s max
- Respawn via `/usr/local/bin/nullclaw-respawn.sh` (while-true loop)
- `start-stop-daemon` for PID management
- `deploy-bots.sh` — scp init scripts, `update-rc.d defaults`, create home dirs
- `cloudflared-init.sh` — separate tunnel service for remote access

Nullclaw also has `nullclaw service install` which generates its own init script
with inline respawn loop (no external respawn script needed).

EC2 (AL2023) has systemd but NOT `start-stop-daemon`. SysVinit script only
testable on pogoplug or Debian container. No tests needed for service scripts.

## Telegram Stale Message Replay (nullclaw open bug)

## web_fetch (from nullclaw)

`src/tools/web_fetch.zig` approach:
- HTTPS only (SSRF protection — blocks private/local IPs)
- Domain allowlist (optional, skips SSRF check for trusted hosts)
- DNS pinning via curl `--resolve` (prevents rebinding attacks)
- HTML → text: strip script/style/noscript, preserve headings/links/lists
- Truncate at 50K chars (configurable 100–200K range)
- External content wrapping: `<<<UNTRUSTED_EXTERNAL_CONTENT id="<16-hex>">>>`
  with marker sanitization (homoglyph folding prevents fake boundary injection)

For CClaw: simpler. Use libcurl directly (not subprocess). Same HTML-to-text
and boundary wrapping pattern. V15 already covers the wrapping requirement.
